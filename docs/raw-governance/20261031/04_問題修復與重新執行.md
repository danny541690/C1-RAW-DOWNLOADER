# 4,008 項問題修復與重新執行

範圍：2026-10-31 已查證之首輪 4,008 項 held 任務。這是凍結問題批次，不是全資料庫缺失總數。首輪 65,238 任務與其封存紀錄保持不變，第二輪另記修復結果，不將例外灌入已下載數。

## 本次修正

- 月營收依序以 UTF-8、CP950、Big5-HKSCS 嚴格解碼。32 份真實問題原件中 28 份可無損解碼；其中 25 份可沿用既有正式 RAW，3 份來自隔離證據，必須重新驗證後透過本地 PROMOTE 存成正式 RAW 並讀回驗證。另 3 份查無公司資料、1 份仍有無法解碼字元，繼續列為待查。禁止忽略或替換字元後自動放行。
- 新增獨立問題恢復排程，從 347 個固定 commit 的封存批次取出精確的 4,008 個問題任務，逐項核對 key、日期、狀態與累計嘗試次數。正常成功項目不重新下載。
- 保留原首輪進度；在各來源狀態的 `problem_recovery` 另記新結果與證據 commit。例外、基本驗證通過、仍待查分開統計。所有 numeric_verified、pit_verified、full_acceptance 仍為 false。
- 已完成的問題來源在設定每十分鐘喚醒時跳過，不反覆重驗。未完成者依持久化紀錄續跑；與原來源 worker 共用來源 concurrency group。
- MOPS 僅對先前明確 HTTP 404、沒有既存 RAW 的國內 `_0` 分區，於剩餘額度內嘗試同官方主機的早期無尾碼入口。本批符合條件且仍有額度者 108 項。這是候選查詢，不預先宣稱路由有效或資料存在；回應仍須驗證月份與公司資料、不可覆寫存檔、讀回 SHA 及回執。
- 來源請求使用原正式 Coordinator 與共用速率預算；累計最多 4 次，不歸零。本地隔離原件轉存使用獨立 materializations 計數，不消耗或重設來源額度。
- 2 項回執錯誤先重新核對既存原件與綁定，不能直接認定內容損毀或觸發重抓。
