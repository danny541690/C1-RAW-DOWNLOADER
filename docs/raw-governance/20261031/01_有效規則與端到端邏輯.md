# 七來源 RAW 有效規則與端到端邏輯

版本 JARVIS_RAW_PLAYBOOK_20261031_V1。規則採納、程式實作、測試通過、正式運作、資料驗收是五種不同事實，分開記錄。
本版整合 2026-10-21 五階段規則、10-27 七來源37條驗收契約、10-29 RAW有效規則及10-30正式啟用／恢復修訂；後續使用者明確指示優先。

## 一、資料範圍與來源

研究期間自 2000-01 到執行日官方已公布的最新資料。未公布資料不可預抓或判為錯誤，來源不提供的歷史需留原因，不填0。
分析僅上市／上櫃；興櫃原件可保留，分析保持停用。前導零、ETF等證券類型是否納入需由需求母體明定，不以正則表達式靜默丟棄。

| TWSE | 上市價量、籌碼、估值、事件等官方原件 | 每張表的起點、歷史主檔、實際內容日期與價格基準 |
| TPEx | 上櫃對應資料；興櫃僅保存 | 舊路由、表頭、單位、市場別及日期格式 |

| TDCC | 持股級距／人數／股數／比率 | 實際發布週曆、當期適用證券、特殊級距及官方可選日期 |

## 二、每個資料單元的完整處理順序

| 步驟 | 判斷及動作 | 產生的證據 |
|---|---|---|
| 1 定義應有資料 | 核對來源、資料集、市場／證券、期間、頻率及官方可提供範圍 | 需求版本、適用性證據、expected keys |
| 2 對帳既有原件 | 先找0.93原件及收據，核對雜湊與身分 | 原件參照、bytes、SHA、內容期間 |
| 3 選擇動作 | RETAINED驗舊檔；MISSING補缺件；REPAIR修確定錯件；PROMOTE移交已保存材料 | action、原嘗試次數、適用契約、來源證據 |
| 4 有界取得 | 源站請求前保存intent；已成功者跳過；尊重共用配額 | request intent、去密鑰參數、結果分類 |
| 5 原件保存 | 保存完整來源bytes及原生單位；修訂另版，跨月保留父回應與分片血緣 | locator、raw SHA、大小、來源／擷取時間 |
| 6 遠端讀回 | 讀回Drive實際bytes核對SHA，必要時檢查前後版本穩定 | readback SHA、穩定版本、原件可讀證據 |
| 7 基本語意驗證 | 日期、代碼、契約／盤別、格式、必要欄與空回應分類 | parser／validator版本、逐項結果、缺漏 |
| 8 持久進度與接續 | 同提交保存分頁索引與任務狀態；先保存再續派 | commit、owner/fence、游標、outbox／receiver |
| 9 深入驗收 | 核准母體、全部必要數值、跨來源同語意及PIT另驗 | expected/actual/checked/uncovered、vintage |
| 10 關閉或重開 | 同SHA先VERIFIED後CLOSED；新問題追加REOPENED | 事件ID、前後SHA、理由、驗收artifact |

缺件或錯件必須明確進入可執行修補佇列。現在有型別化橋接能力，不表示所有 HOLD 已自動轉為修補。原件讀取或內容失敗後列阻擋，不能向使用者說「已補完」。

## 三、持續有效的規則

| ID | 規則 | 目前執行或限制 |
|---|---|---|
| R01 | 成功資料不重抓，按單元去重，不按整月有檔就跳過 | 已接入原件／收據綁定；全庫尚未全部驗證 |
| R02 | 原件不可靜默覆寫，錯版／修訂另存 | 保留新舊SHA與supersedes；版本衝突需審核 |
| R03 | RAW保留原值與原單位；展示金額用億元 | 價格、每股值、股數、口數、百分比保持自然單位；外幣另明幣別 |
| R04 | 查詢日期、內容日期、交易日、報告期、公告時間、擷取時間分開 | 改檔名不會修正錯日期；未知日期隔離 |
| R05 | 空白／--／N/A／0／非交易／不適用／未發布分開 | 不將空回應當取得成功或歷史不存在 |
| R06 | 官方優先，FinMind補件獨立留存 | 補到研究所需值不自動關閉官方原件缺口 |
| R07 | 重試三次＝初次1＋追加3，最多4次來源請求 | 依同邏輯任務持久累計，重啟／改版不重設；舊特定五次配置不套現版 |
| R08 | 限流／逾時／暫時5xx才有界退避；尊重Retry-After | 認證／參數／內容／適用性分流，系統錯誤按來源暫停 |
| R09 | 不明中斷先對帳原件與收據，再決定請求 | 不能直接重送，也不能永久略過未確認單元 |
| R10 | 已保存但未ACK的資料，只恢復讀回／收據／報告 | 不因summary失敗重抓市場；本地移交次數、恢復次數與來源請求分開 |
| R11 | 同來源單一有效寫入者，ASC／DESC輪替 | 12條是邏輯方向槽，不等於12條同時全速；不同來源可並行 |
| R12 | 發送前持久outbox，同來源最多一個未確認續派送 | 晚到receiver先驗identity/fence；不強行退休仍活躍owner |
| R13 | 分頁狀態索引與內容固定同一commit | 統計＝archived_status_counts＋該commit當前頁；不能只加last_batches |
| R14 | release開關及完整程式指紋驗證 | 變更scripts／workflow需重新驗證指紋；本次只寫docs不改執行碼 |
| R15 | 存檔、基本QA、數值、PIT、全庫驗收分開 | RAW_BASIC_VERIFIED不是全面驗收；布林自填true不能當證據 |
| R16 | 缺值不人工補價、不任意擴大容差 | 合法負值依欄位解釋；母體未知不得當零缺漏 |
| R17 | 最新更新與歷史補庫各保留斷點 | 固定清單結束不等於永久每日更新已完備；未發布狀態需重新查證 |
| R18 | 第二層按輸入SHA／規則版本增量重算 | 歷史補件後只更新依賴範圍；不能宣稱全部下游已接通或核准 |
| R19 | 事件追加，歷史失敗不改寫成功 | 原錯誤、失敗／取消／跳過與新成功分別保留 |
| R20 | 每份進度標示時間、母體與動作 | 檢查數、新下載數、移交數、修復重驗數、隔離數分列，不相加冒充下載 |

## 四、現行排程與復原

目前12槽：TWSE 1-1/1-2、TPEx 2-1/2-2、MOPS 3-1/3-2、TDCC 4-1/4-2、TAIFEX 5-1/5-2、NDC 6-1、FinMind 7-1。
前五來源各DESC新到舊／ASC舊到新；NDC、FinMind單向。舊「集保5／期交所6」是舊版編號，不用編號單獨識別來源。

正式模式共用 `jarvis-v093-production-{source}` 互斥，同來源輪替，處理預算45分鐘，workflow上限60分鐘。
watchdog cron為每小時3、13、23、33、43、53分，加手動／設定推送／完成事件入口。cron時間不保證準點實際執行。2026-10-31本次最近100個run未見完成事件觸發watchdog，不宣稱已觀測此路徑。
控制器遇來源任一方向仍在執行時延後，不與worker競寫。續派送恢復最多4次，和來源請求最多4次是不同計數。

程式現行保守來源預算與FinMind會員上限不是同一件事。適配器目前FinMind reserve limit=200/hour，其他來源30/min，spacing=2秒；TDCC新查詢成本記2。既有原件讀回主要耗Drive/GitHub，不應說成集保源站限流證據。

## 五、完整率與第二層

完整率需先有「資料集×內容日期／期別×適用證券／欄位」的分母，再核對實際原件內有效觀察值；日週月季不能混用。
年度包先解析實際日期，不能乘12假裝12月檔。只有月檔不證明全序列／全公司／全欄位齊全。
另列官方可取得範圍取得率與2000年至今研究需求覆蓋率，不能因來源限制刪掉研究需求就宣布100%。

2026-10-27帳本337,023項、99,700有原件參照、80,488基本格式存檔通過，是舊查詢單元盤點，非全庫觀察值分母。
65,238是本輪固定清單，不是六萬多份新缺件。先前64～69%僅條件性盤點情境，不可再作全庫完成率。全庫數值／PIT／完整率仍未核准。

第一層先形成版本基準，通過適用基本條件的單元可進第二層暫存；未知／錯誤保留原因。公告時點／修訂未證實者不得冒充可用於當時回測。
月10日合併上月屬既有STANDARD政策，晚到修訂另版，不保證所有來源在10日已公布齊全。
