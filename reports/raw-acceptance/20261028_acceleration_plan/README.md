# 賈維斯最少輪次整體驗收計畫（2026-10-28）

結論：以「一次完整主批次＋必要時一次補正批次」為工程目標；通過後的發布、讀回與下游驗證放在同一流程的最後階段。這不是兩次必過的承諾。此文件是待落實的執行計畫，目前沒有宣稱已建成或啟動完整八組流水線。

## 現況與檢討

已確認 PR43 合併，完整程式回歸 846 項通過；實際資料批次有 562 筆部分內容證據，包含六檔興櫃 120 列、480 個高低量額欄位對一致，仍為 RAW-only。讀回範圍內剩六個 2001Q1 財報檔案阻擋。八組整組仍 0 完成、6 部分、1 未確認、1 阻擋；正式分析與回測核准範圍 0。

目前 337281 是凍結單元與補存版本的混合清單，不能作完整性分母。99390 本機未讀回不等於遠端不存在；237323 舊清單缺原件候選需對帳最新收據。六個內容阻擋亦不是全資料庫僅剩六個問題。

主要流程缺點：

1. 把程式回歸成功與真實資料驗收進度放在一起，掩蓋尚缺母體與 PIT 等必要證據。
2. 已有 37 條規格，但沒有單一完整執行器與全組可結案的實際證據；外部比對及復原結果也尚未統一彙入。
3. 多個 workflow 中有模擬案例、結構檢查及軟體回歸，不能直接算成全量資料驗收。此次未重跑這些舊 workflow，也不以舊靜態診斷斷言目前正式環境仍有同一競態。
4. 現行 checkpoint 簽章納入 scripts 下所有 Python 檔，無關腳本改動也可能導致全部內容重驗；應改用真正相關依賴與證據指紋。
5. 未在一輪結束時把「無實作、缺證據、來源限制」分開，使用者被迫重複要求繼續。

## 第一批次：完整主流程

準備、盤點、執行與彙總均在這一批次內；不另把準備工作包成一輪驗收成功。

| 階段 | 主要工作 | 結束條件／失敗處置 |
|---|---|---|
| P1 凍結範圍 | 維持 2000～2026 全歷史目標；逐來源、資料集、日期、歷史證券建立應有母體，標註依法已發布與尚未到期。對帳目前 Drive 原件及最新收據，分清邏輯資料與補存版本 | 沒有可核定母體，完整率 UNKNOWN；仍可繼續其他有依據的查驗，不讓單一失敗中止全批次 |
| P2 一次讀回 | 依唯一 package ID／版本去重讀回；CRC、SHA、成員範圍、日期主鍵；保存不可變輸入 manifest | 登入頁、空回應、截斷、hash 衝突不算下載成功；先找既有正確原件，再判斷重下載 |
| P3 合併驗證 | 各來源已就緒的工作併行；每個來源內按契約、日期主鍵、空值、單位、數值、跨來源、PIT 的必要依賴執行；一次產生全部錯誤 | 未實作檢查器必須列 NOT_IMPLEMENTED_BLOCKED；不可只執行已實作部分便稱全驗完成 |
| P4 復原與鮮度 | 對同一候選 generation 在獨立目錄／執行環境復原，讀回原件與成員 SHA、檢查時效；可與 P3 無依賴部分併行 | 現有七檔局部復原不得代替整個核定範圍；同帳號復原也不得宣稱帳號遺失災難復原 |
| P5 一次彙總 | 匯入所有八組真實證據及 37 規格逐項結果，綁定同一 scope、generation、input digests 與驗證器版本 | PASS、FAIL、UNKNOWN、附證據 N/A 四態；缺證不得變成 true；沒有錯誤列但沒執行也不算 PASS |
| P6 有條件發布 | 僅對全部必要閘門合格的明確範圍：發布 manifest／Parquet、讀回 SHA、正式下游載入、實際計算／回測、回復前版檢查 | 條件不足跳過發布並列明阻擋；只做模擬發布不得宣稱正式可用 |

P1/P2 是必要前置；P3/P4 無相依部分可併行；P5/P6 在證據齊全後接續。七來源查驗可併行，但對外抓取仍共用現有來源限速與鎖，不新增互相爭搶的下載排程。

## 八組結案責任

| 組別 | 必交付的結案證據 | 目前最重要缺口 |
|---|---|---|
| R01 母體與原件 | 核定應有觀察值與現存資料逐鍵對帳，能區分未到期、不適用、未下載、未知 | 尚無核准全庫分母；舊清單與最新收據對帳 |
| R02 歷史證券日期主鍵 | 歷史市場有效期間、交易日／事件日、逐鍵日期與唯一性 | 六檔興櫃只證明了已查範圍，不代表全部歷史市場已覆蓋 |
| R03 欄位單位契約 | 所有納入範圍資料集有版本化定義、單位、零值與例外規則 | 不能把一般股票 OHLC 規則套至興櫃；其他資料集契約亦待齊 |
| R04 全量數值 | 全部適用原件可讀回、全量數值與關係檢查覆蓋、缺失逐項閉環 | 六個早期財報；大量既存原件未在本次讀回檢查 |
| R05 跨來源 | 同鍵、同單位、同口徑、同調整基礎的比對；上游獨立性說明 | 19000 欄位對診斷一致不等於已具獨立性或完整範圍 |
| R06 PIT 與版本 | 原公告可得時間、原版／更正版、AS_KNOWN 選版規則 | 本次下載時間不能代替歷史公告時間 |
| R07 發布下游 | 現有九項必要 QA 實際證據、候選資料 SHA、發布讀回、下游運算與回復紀錄 | 前置未合格；正式核准範圍 0 |
| R08 復原鮮度 | 核定範圍的實際復原 SHA、來源鮮度與失敗重試證據 | 現有證據只有局部七檔、283 個登錄單元 |

37 條規格已一對一分配主責組，見 rule_ownership.md；這是執行責任草案，不改變原規格、不代表規格已通過。發布既有九項必要 QA 為 sha_readback、schema、unit、unique_key、numeric、universe、pit、source_contract、dependency。

## 第二批次：只補正與重驗受影響範圍

第一批次輸出完整修補清單後，第二批次統一處理：可修程式、需讀回既有原件、確定需重下載、來源限制／等待、需釐清證據。優先使用既有成功 RAW，只有證實資料缺損／原件錯誤才重新下載；保留失敗回應及原始版本，不覆寫。

- 同一來源失敗遵守現有三次上限、冷卻與路由規則，不重設已到上限任務，不持續重試空回應。
- 程式、契約或原件變更只使相關鍵與下游依賴失效；變更共享基礎程式則仍須完整相關回歸，不能為省次數跳過必要 CI。
- 全批次必須先收集各組錯誤，再彙總，避免修完第一個錯誤才看見第二個。
- 第二批次仍缺官方證據，直接列 BLOCKED／UNKNOWN 與下一個可行動條件；不得稱本輪全過，也不自動展開無限第三、第四輪。
- 中斷後以最後成功 checkpoint 接續，不要求使用者重新逐輪發指令；工具或服務中斷時要說明已完成、未完成與下一步。此次文件尚未建立背景自動執行承諾。

## 加速實作清單（先做完再啟動全量主批次）

1. 單一協調入口：整合八組 checker、37 規格結果與發布依賴；缺 checker 直接阻擋。既有實際來源檢查器可重用，不另建一套重複測試。
2. 最新遠端 manifest 與可核定母體：完整列舉，處理搜尋分頁／top_k 截斷；依來源／資料集粒度對帳，避免年度包乘 12 或股票候選名單充當分母。
3. 每個 package 一次讀回、一次解壓，結果分享給各 checker；RAW immutable、磁碟快取與 bounded memory；網路斷線續傳不等於來源重下載。
4. 依賴範圍 checkpoint：raw SHA、母體版本、契約版本、相關 parser/checker 簽章、PIT 證據；先驗證 signature 再沿用結果。對證據變更及跨 scope 錯用做必要測試。
5. 一次性輸出：總表、七來源表、來源／年份／月份追蹤、37 規格、八組狀態、失敗及未知、修補履歷、發布／回復證據，同一 run_id 對應 GitHub／Drive／ChatGPT。

這五項尚未在本次文件工作中全部實作，不能直接把現有批次當作新完整流水線使用。現有入口只做讀取登錄表與本機保留原件內容驗證，不能替代遠端全量對帳、全組 PIT、獨立比對與正式發布。

## 上線與完整性兩個里程碑

- 全歷史目標維持 2000～2026；只有在相同已核定範圍內八組必要條件通過，才能稱該範圍八組完成。不可把排除難解來源當成全庫完成。
- 若先找到可獨立合格的來源／資料集／期間，可提出明確候選發布範圍，逐項驗收後發布；本文件不擅自核准或縮減正式範圍。
- 單月價格資料不能直接代表完整策略回測能力；必須包含策略使用的全部欄位、交易日、公司行動及暖機依賴。無 PIT 證據的來源不可宣稱可做歷史當時可得的正式回測。
- 100% 完整性只能針對核定且已到期的母體計算；未確認、尚未到期與來源不存在需分開報告，不把 UNKNOWN 排除來美化分母。

不給缺依據的完工日期。先完成母體／遠端讀取試量與 checker 盤點，依實測工作量、來源限速及缺證情形估算；耗時變長不等於需要使用者多輪發指令。
