## Autonomous operation in 2026
The 2026-only controller checks recent source runs, skips active source writers, dispatches idle overdue source flows in bounded fanout, schedules separate QA if overdue, writes one auditable controller receipt. No forced redownload and no modification to successful partitions. Existing source cursor is authoritative. Do not self-promote when a workflow returns success. Scheduled GitHub cron can be delayed or dropped; use durable state + watchdog rather than relying on cron as guaranteed.
Market calendar denominator must use official eligible trading/release dates, not calendar days or Monday-Friday counts. Per dataset report raw_saved/QA_pass/Silver/Gold_descriptive/Gold_PIT/lineage_pass and quarantined/NOT_APPLICABLE; each percent has numerator and denominator.
Historical valuations, 24-month revenue highs, TTM, Stage3->4 and RS require data warming period and actual release vintage; no 2026 opening-day Gold assertion without preceding historical lookback.

## R2 operational decision 2026-11-08: six priority intake lanes and iterative convergence
User authorizes first pass through 2026-01-01 to the most recent actually published data, **not** January 2026 through unobserved future dates, with independent QA and downstream catch-up, then a second/third incremental defect pass. Six source lanes TWSE, TPEx, MOPS, TDCC, TAIFEX, NDC retain distinct single-writer groups; a controller may dispatch up to six *different* idle source workflows. Source-specific native checkpoints and SHA reuse remain authoritative. TWSE/TPEx existing source cron 15 minutes, other four 30 minutes; controller checks every 30 minutes and now considers TWSE/TPEx idle after 20 minutes or other sources after 35 minutes. Existing cron should continue if controller cannot run. Verify in action run receipts, not assumed constant occupancy or exact timing.

**Current functional limitation:** six legacy source workflows are source-scoped, but each still couples Bronze collection with some Silver or Gold candidate processing in the *same job*. This R2 change prioritizes Bronze source dispatch and independent hourly read-only QA; it does not misrepresent those workers as fully decoupled 18-stage production jobs. A truly separate S01/S02/G01/G02 must be introduced in shadow mode and proven idempotent, using immutable SHA inputs and partition locks, *before* changing existing source workers or doubling Silver/Gold writers. Never start a separate stage writer over existing destination partition without a non-overlap gate or atomic CAS.

Iteration 1: advance all source cursor lanes, accept only native immutable bytes/CRC/manifest/SHA and retain per-dataset nullable exceptions; existing safe candidate downstream work may run but never blocks independent sources. Independent QA checks any existing data separately, reporting formal completion only when evidence exists.
Iteration 2: use missing partition/retry queue and exact source/dataset/period, auto recover transient 429/5xx/timeouts at most three attempts, reuse successful Bronze and avoid reprocessing same source SHA+adapter version. Schema/ZIP/announced-at issues go to quarantined exceptions, **no looping HTTP**.
Iteration 3: targeted QA/typed Silver/Gold/PIT/bidirectional lineage revalidation, only affected dependents; missing historical source data or missing lookback makes Gold NULL/disabled and marks PIT not certified. A source/dataset is DONE only with credible denominator, SHA readback, complete processing and release gate, not after one cursor sweep or green workflow. Maintain report counts for visited/accepted/missing/quarantined and candidate-vs-certified percentage.
Capacity constraints: six source jobs + one independent QA + one bounded supervisor is a scheduling **ceiling for distinct active lanes**, not proof of available physical runners, source quotas or present simultaneous utilization. Tune down fanout on real Drive 429s, auth errors or source rate-limits. A single-source job never receives a second concurrent writer. Source-specific concurrency protects a lane but not all shared Gold: any new Gold worker must adopt partition CAS. Do not enable 2000-2025 or production flags.
