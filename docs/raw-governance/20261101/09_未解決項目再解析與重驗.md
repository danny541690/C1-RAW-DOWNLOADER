## 查明的原因與修正

1. 舊 problem-recovery 排程以 finished 作跳過依據。這個旗標表示一輪清單已走完，即使仍有 REVIEW_REQUIRED，後續喚醒也不再讀原件。新增獨立、可續跑且逐項留痕的未解決原件重驗排程；不重置既有基準，也不將 review_complete 當 all_issues_resolved。
2. 櫃買靜態 Oracle 報表 O/H/L 全為字面值「.00」時，漲跌欄可能不是 0。原解析器要求漲跌為 0，誤將未提供完整 O/H/L 的報表擋下。實例：2003/08/15 的 6502 漲跌 -5.90、2003/08/21 的 8721 漲跌 -1.59、2003/08/26 的 8725 漲跌 -0.29。
3. 修正僅適用已查證的靜態報表：O/H/L 三欄都明確是「.00」才標記未完整報價。保留原值，不推定零元交易、成交盤別或收盤欄語意；不檢查這些列的完整 OHLC 關係、不聲稱數值完全正確。真實正值 OHLC 關係錯誤、部分零值、負值、錯日期、替代字元仍不可放行。
4. TPEx 在 HTTPError_403 保護性暫停中。先前連完全不發市場請求的 PROMOTE 存檔都被一起擋住。本次只允許 local_only=true 且 execution_contract.mode=PROMOTE 的已保存原件，在 403 仍保留時做驗證、存檔與讀回。Native HTTP 對 PROMOTE 明確禁止；一般下載、偽造 local_only 的 MISSING 工作仍受來源 hold 阻擋。沒有清除 hold、沒有換 IP、代理或繞過來源拒絕。
5. 成功結果移除過期錯誤與待重試旗標，歷史錯誤另留 resolved_error；不讓舊隔離證據覆蓋剛通過原件的證據引用。
