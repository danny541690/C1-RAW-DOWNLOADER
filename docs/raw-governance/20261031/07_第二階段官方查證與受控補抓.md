# 第二階段：官方查證與受控補抓

本輪針對已封存問題來源，不重設既有首輪／第一輪修復進度。MOPS 原修復排程與 TDCC 原排程繼續使用原斷點。

## 程式修正

1. 自動報告不再因單一檔案超過 700,000 bytes 直接失敗。Git 控制紀錄依 Unicode 字元邊界分卷，每卷編碼後不超過 600,000 bytes；原始檔名稱、總長度、SHA 與分卷關係寫入清單。Drive 以不超過 650,000 bytes 的 JSON 分卷保存，所有分卷讀回後重組比對完整紀錄，再保存索引。總量 10 MB 與來源路徑邊界限制仍保留。
2. 官方年度日曆必須同時核對回應年份、標題年份與資料列日期。不因網址含年份就認定查對年份；開始／最後交易日不列為休市；未出現在年度表格的平日也不證明當天開市。
3. TPEx 依官方全國股市週六不交易的制度日期，僅將 2001 年以後的週六空回覆列為例外。2000 年週六保留待查。其他休市分類附年度官方原件 SHA 與網址。
4. TWSE、TPEx 空回覆進入第二階段。只有官方日曆已核對、日期位於已確認現行入口適用範圍、原件及來源契約可綁定、尚有請求額度者才受控重新查詢。年度日曆沒有列出的平日，只代表可作一次有額度的查詢，不代表已證實有資料。
5. 既存空回覆保留，下載到的新版本依原生不可覆寫規則保存。回應仍需通過日期、欄位、資料列、存檔、讀回雜湊與回執驗證；再次空回覆留待查，不能變成下載成功。
6. 舊版櫃買入口先探測官方頁面、實際列出的腳本、表單及 API 路徑。未證實正確欄位、日期與查詢方式的入口，不自動拼網址大量下載。公網入口不可存取時記錄錯誤，不宣稱資料不存在。
7. 所有來源請求與原 worker 共用來源 concurrency、正式 Coordinator、速率預算與原累計次數，上限 4 次。年度日曆／入口探測另有持久化 metadata 次數，同樣最多 4 次，不使用市場資料任務的額度歸零技巧。
8. 報表新增 analysis_complete、processing_pass_finished、still_open、all_issues_resolved，分開說明本輪處理結束與資料問題是否全數解決。

## 實測與驗收

- 原有完整測試加新增分卷及官方查證測試。
- 真實 TWSE 802 項、TPEx 2,833 項報告在隔離環境重播：分卷與讀回重組完全一致。
