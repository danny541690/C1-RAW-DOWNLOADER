## 確認的重驗缺陷與修正

原 unresolved-recheck 仍釘住舊 TWSE 154 項與舊 MOPS 修復狀態，且 review() 總是把凍結第一輪 task 交給 recheck()；後來取得的 followup_rejected_evidence 沒有被使用，導致 2004/09 新下載原件未進入這個重驗流程。

V9 釘住最新 TWSE 152、MOPS 133 狀態。優先選取最新 followup_rejected_evidence，其次 previous.rejected_evidence，否則才回到第一輪原件。最新隔離原件須核對同一 task 身分、儲存 gzip SHA、解壓 bytes 長度、原件 SHA，再依原驗證器核對日期、表格、代碼。原件和凍結合約不修改。

為共用已驗證讀回器，隔離原件只在記憶體中的複本視為可讀取參照；即使驗證成功，結果仍強制 REVIEW_REQUIRED／VALID_REJECTED_RAW_REQUIRES_PROMOTION、accepted_as_raw=false、raw_writes=0。必須另經 Native 正式保存及讀回才能計入 RAW。本輪重驗本身來源請求為 0。SHA 不符不得回退舊檔假裝通過。

## 證交所既有空回應的有界復測

官方每日收盤行情頁 https://www.twse.com.tw/zh/trading/historical/mi-index.html 明載自民國 93/02/11 起提供。最新 152 件中 151 件仍有請求額度，另 1 件已四次。設定檔逐 key 凍結日期、原累計 attempts，僅允許既有 TWSE prices_indices、2004/02/11～2026/10/31、REVIEW_REQUIRED 且原理由為官方空回應（或精確 ApplicabilityUnproven/VALIDATE）的項目。

這次將「缺少年度休市表」與「能否再查詢已知官方入口」分開：沒有休市證據仍可做一次已授權的既有缺口查詢，但不能因此認定該日有交易、歷史不存在或已補齊。仍讀回原空回應並核對 SHA，再由既有 Native Executor 處理；正確原件不覆寫。每 key 最多追加一次，與原累計四次上限取較小者；不重置 attempts。新回應仍空、錯日期、格式或儲存未通過就維持 REVIEW_REQUIRED。

正常來源鎖、速率預算、冷卻與暫停旗標繼續生效。持久 journal 防止重跑同版清單時反覆請求。單輪補抓最多 1,800 秒，未完成清單於每小時 07、37 分排程續跑；GitHub 排隊和來源鎖可能延後，已處理 key 不再請求。此排程只處理 TWSE，既有 TPEx 補抓不更動。
