## 清單架構

1. 下載主清單：ZIP中的「單元主清單.csv」與units內七來源壓縮CSV，完整337023單元，兩者內容相同。
2. 取得缺口：篩選「取得缺口待核實=1」，保留尚未嘗試與取得失敗。
3. 品質問題：篩選Q1；同時保留開放檢查、官方缺口及未補日期等次要問題。
4. 五類及其他問題字典：Q為五主類，O為額外待處理，P為狀態，避免所有問題硬塞五類。
5. 來源／年份／月份對帳：2254列=7來源×322月，另有189列來源年份與7列來源總覽。零計畫代表未建立可確認計畫，不能解讀為完整。
6. 日期與時間追蹤：歸屬月份、期間、明列未補日期、原帳本更新UTC/台灣時間與原始日期語意分開。未補日期數61為來源/查詢相關次數，不是去重後全市場缺日數。
7. 範圍與待確認：歷史母體、來源最早日期、停牌/下市、上市/上櫃/興櫃身分、報表公司組及公告時間仍需核定。
8. 修補事件簿：repair_events.csv追加事件，保留修補前後SHA、原件、執行證據、時間、原因與驗收人。

## 後續修補與查詢

固定任務ID=SHA256(來源|月份|單元ID)前20碼。原始快照保留，修補只追加事件：DOWNLOADED→VERIFIED→CLOSED；發現問題追加REOPENED。QUALITY_REVIEW可記錄尚未通過的檢查。

`python3 register.py find --source TWSE --month 2026-07 --limit 20`

`python3 register.py record event.json`

`python3 register.py rebuild`

事件必填task_id/source/month/unit_id/event_type/event_time/reason/reviewer。event_time需含時區。下載或驗收事件需new_sha256、new_file_ref、run_url、remote_hash_verified=true。VERIFIED/CLOSED另需period_verified、security_verified、numeric_verified、pit_verified、unit_scope_verified均true且unfilled_count=0。先VERIFIED後CLOSED，且同SHA才可關閉。適用性或PIT未完成就保留開放，不填假true。工具檢查填報完整性，實際證據仍需驗收人查核。

current_monthly.csv依事件重建目前狀態，原始來源年月表保留當次基準。重開時不抹除已下載原件；同事件重送不重複。Excel填報頁不會自動追加事件或關閉缺口。此版尚無實際修補事件，也沒有新增自動同步排程；未改動既有市場下載作業。
