## 下一次接手的固定步驟

1. 讀本索引、有效規則、未結事項與evidence_registry，確認最新版及適用日期。
2. 讀 `config/v093_source_release.json`、`config/v093_seven_source_design.json`、目前main SHA。舊文件不是live state。
3. 查GitHub Actions真實run／job／event，區分active、queued、failure、success、cancelled、skipped。
4. 每來源先固定 `jarvis-source-state/{SOURCE}` commit，再讀state.json與該commit全部頁。加總歸檔與當前任務；不要混讀不同HEAD。
5. 發現中斷先查lease／owner／fence、request/save intent、outbox、Drive原件／收據SHA。仍活躍的worker不要重啟或奪鎖。
6. 依RETAINED／MISSING／REPAIR／PROMOTE分流，保存原嘗試次數。修補方案先做代表正反案例，再只處理受影響範圍。
7. 報告分列檢查通過、新下載、修復重驗、移交、隔離、來源限制及未知。不能從RAW_BASIC_VERIFIED逆推新下載數。
8. 以追加事件更新本知識庫，保留舊錯誤及新證據。程式／workflow變動需重驗release指紋；文件更動不冒充重新跑全套市場驗收。

## 可以貼到新對話的接續指令

請延續 JARVIS C1 v0.93，先讀 GitHub `docs/raw-governance/README.md` 與 `docs/raw-governance/20261031/` 的規則／問題／證據索引，再查正式release及七來源固定commit狀態。官方優先、成功不重抓、RAW不可靜默覆寫、初次1＋追加3持久計次；目前只收盤後日頻及較低頻／公告資料，排除盤中。保留所有斷點、原件與收據，未知請求先對帳。檢查失敗不等於自動補抓，核定REPAIR後才修。分開工作流完成、基本QA、數值、PIT、全庫完整率，完整率分母未核准保持UNKNOWN。不要把過去五條／六條的編號與時限當現版12槽設定。
