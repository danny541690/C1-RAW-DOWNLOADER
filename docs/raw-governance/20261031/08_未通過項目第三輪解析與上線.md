# 未通過項目：第三輪解析及重新上線

本輪接續既存問題狀態，不重建基準、不歸零請求次數、不重新下載成功原件。

## 實際查證的問題

1. 櫃買 2007 年初的官方頁面 `pricing_hist96.html` 使用 `afterTrading/dailyQuotesHis`，而不是現行每日行情入口。官方 `main.js` 定義 `/www/{LANG}/{ACTION}`，官方 `tables.js` 使用 POST，日期為 `yyyy/mm/dd`。回應中的 `html` 必須轉成表格檢查，不能套用現行純 JSON rows 驗證器。三份官方原件 SHA 已釘選在設定檔。
2. 2003～2006 年官方 `param_3104.html` 是頁框入口，實際指出 `RSTA3104QRY.HTML` 與 `RSTA3104RES.HTML`。前輪只保存入口及通用腳本，沒有追到查詢頁框；本輪優先讀取官方實際列出的頁框，不自行猜測下載檔名。
3. 日曆解析器漏判單獨寫「補假」的日期。本輪重讀保存的官方 JSON 日曆補正分類，不額外花來源請求額度；已重新查詢仍回覆空資料者也可在取得精確休市證據後重新分類。
4. 舊年度 JSON 日曆可能年份正確但資料列為空。新增官方舊 HTML 年度日曆候選入口，嚴格檢查頁面標題與內文年份、日期及休市說明；錯年份、無表頭、合併不明資料列、空表都不能放行。此探測仍計入該年度累計最多四次的 metadata 額度。

## 新增驗證與執行規則

- 櫃買早期 API 僅准許 2007/01/02～2007/04/20。先處理固定真實缺件 2007/01/02；必須驗證、保存及讀回成功，才放行同區間其他項目。
- HTML 必須有可辨識的日期證據；回應日期或表格標題日期不符均封鎖。檢查代碼、表格寬度、重複代碼、OHLC 關係、成交股數與成交金額，並維持至少 300 個四位數公司代碼的既有基本市場門檻。
- 原始 bytes 不轉碼覆寫、不換單位；解析結果只表示基本驗證，不宣稱完整數值、歷史母體或 PIT 驗收完成。
- 失敗新回應的隔離證據引用會寫回 followup 狀態，避免移除臨時工作項目後遺失解析線索。
- 沿用原正式來源鎖、速率預算、初次加三次共四次的請求上限。年度日曆／頁框探測次數也持久保存。
- 統計沿用原 802 個 TWSE 與 2,833 個 TPEx 問題項目，第三輪覆蓋同來源上一輪結果，不能重複加總。
