# JARVIS C1｜GitHub 專用 SOP 0.94 R1
2026-11-02重整；與總規則共同使用。本次整理程式位於隔離ops分支，正式main和12槽未改動。

GitHub保存可追蹤程式、來源契約、規則版本、小型發布入口、CAS任務狀態及測試。市場RAW、大型Parquet、私密憑證不得提交Git。Secrets只經現有執行環境注入，日誌不印token／refresh token。Actions runner是可丟棄運算節點，cache與短期artifact不是永久資料庫。

## 執行契約
RAW取得、QA、標準化、分析、報告分職責；同來源單一writer，跨來源並行。12槽是輪替工作入口，不是12個長駐資料庫。採現行配置的短時間工作，預算前儲存checkpoint和回執，異常復原先檢查持久狀態。不可把舊SOP的45分鐘／60分鐘描述套成所有工作固定規格，實際看當前workflow及worker time budget。

狀態至少區分PENDING/RUNNING/SAVED/VERIFIED/FAILED/HOLD/CONFIRMED_EXCEPTION，實際程式狀態名稱以目前schema為準。job綠燈只是執行成功，下載／QA／完整度各有自己的驗收。請求意圖、嘗試次數與lease跨run保存，CAS拒絕過期worker；已存未ACK時從回執恢復，不再下載。同來源雙方向共用額度和狀態。

cron可能延遲，依watermark補執行；watchdog檢查心跳、有效進度、最後成功與queue age，不無限重啟。auth／配額／schema事件要hold或隔離，暫時失敗有限退避；初次加3次重試為生命週期總額。

## 修改與上線
1. 先讀錯誤歷史與官方契約，重現單一問題；能以現存RAW重驗就不要重抓。
2. 工作分支限定改動，保留前後證據；相關單元／整合、讀回hash、日期、唯一鍵與恢復情境必須符合變更。
3. 固定程式commit、規則版本及資料release，檢查相容性。測試紀錄寫明範圍；歷史PASS不代表今天全部通過。
4. 正式切版用現有審查發布流程及回退指標；啟用後看新run及回執。0.94文件建立不觸發RAW或runtime全面搬家。
5. 失敗保留舊可用release，錯誤窗口隔離；rollback保留稽核，不刪失敗證據。

## 成本與留存
看實際帳戶方案、repository可見性、分鐘、artifact與cache用量再估成本，不承諾Actions無限免費。歷史回補、每日更新與低優先QA共用明確預算，完成就降頻；非交易時段不無意義重掃整庫。artifact過期前將必要回執保存Drive／版本索引。程式與文件可追版本，RAW透過Drive ID+hash引用。

## 分析工作
工作節點按manifest只取需要分區，用DuckDB讀Parquet，輸出新的generation；不要多台機器共同改寫Drive上的單一資料庫檔。相同input_digest與規則版本重用。發布必須資料落盤、讀回、品質通過後才切入口；未通過分析不升正式選股或債券訊號。
